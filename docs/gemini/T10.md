# T10 —— 云同步引擎（乐观锁 + 历史快照）+ 前端三方合并同步层

## 1. 背景与目标
打通前后端云同步全链路，消除原版整库覆盖丢数据的隐患：
1. **后端同步与历史快照 API**：
   - `GET /api/sync`：无文档时返回 `204 No Content`；有文档时返回 `{ data, rev, updatedAt }`。
   - `PUT /api/sync`：接收 `{ data, baseRev }`，限制 Body 最大 10MB（超限返 `413`），校验 `data._version == 6` 及核心集合结构。
     - 首次写入（库中无记录且 `baseRev == 0`）→ 写入 `rev = 1`。
     - 库中已有记录且 `baseRev == currentRev` → 原子递增 `rev = currentRev + 1` 并更新。
     - `baseRev != currentRev` → 返回 **`409 Conflict`**，同时在响应体中附带最新的 `{ serverData, serverRev, updatedAt }`，省去客户端二次 GET 请求。
   - **历史快照 (`doc_revisions`)**：每次 `PUT /api/sync` 成功时，若距上次快照 `>= 10 分钟`（或首次创建），自动插入一条快照并生成摘要（如 `世界观:2 组织:4 角色:15`）；同步执行保留策略清理：**保留最近 50 条 + 过去 30 天每日最新 1 条**。
   - `GET /api/sync/revisions`（返回快照元数据列表）与 `GET /api/sync/revisions/{id}`（返回指定快照完整 `data`，供前端预览与一键回滚）。
2. **前端同步状态机与三方合并 UI**：
   - `stores/sync.ts`：管理四态指示器（●绿=已同步 / ●黄=待同步 / ●灰=离线或未登录 / ●红=需人工确认冲突）。
   - 收到 `409 Conflict` 时，自动调用 `threeWayMerge(baseDoc, localDoc, serverDoc)`：
     - 若 `canAutoMerge === true`（两端改的是不同实体或不同字段），静默采纳合并结果并以 `baseRev = serverRev` 自动重发 `PUT`，同时弹出轻提示「已自动合并多端修改 ✓」。
     - 若存在同一实体同一字段的硬冲突，状态灯变红并弹出 `ConflictDialog.vue`（展示差异摘要与冲突字段对比，支持「保留本地 / 采用云端 / 合并后保存」）。
   - 提供 `RevisionHistoryModal.vue`（云端历史版本列表、预览差异、一键回滚到任一历史时间点）。
