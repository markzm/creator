# T00 —— 仓库初始化、Makefile 与 API/Schema 契约

## 1. 背景与目标
搭建前后端分离重构的标准工程底座，确保当前 Ubuntu 22.04 机器上的 Node.js 22 LTS 与 Go 1.27 工具链完备，建立顶层 `Makefile` 统一研发与验收指令，并冻结前后端共享的 `DocV6` Schema 契约。

## 2. 输入参考
- 公共规约：`/data/creator/docs/gemini/00-RULES.md`
- 原版文件：`/data/creator/legacy/index.html`（L459–L491 初始 DB 结构与版本定义）

## 3. 产出文件清单
- `/data/creator/.gitignore`
- `/data/creator/Makefile`
- `/data/creator/server/go.mod`
- `/data/creator/server/cmd/creator/main.go`（最小可编译骨架，支持 `--version` 与 `serve/invite/user/legacy/backup` 子命令路由占位）
- `/data/creator/web/package.json`
- `/data/creator/web/tsconfig.json`（开启 `strict: true`）
- `/data/creator/web/vite.config.ts`（配置 `/api` 与 `/avatars` 代理到 `http://127.0.0.1:8080`）
- `/data/creator/web/index.html`
- `/data/creator/web/src/main.ts`
- `/data/creator/web/src/App.vue`
- `/data/creator/web/src/core/schema/types.ts`（完整的 `DocV6` 接口定义）

## 4. 详细实现要求
1. **工具链检查与安装**：
   - 若系统未安装 Node.js，在 `Makefile` 的 `check-env` 或初始化阶段安装 Node.js 22 LTS。
   - Go 使用 `/snap/bin/go`（已在 PATH 中），模块名定为 `creator/server`。
2. **顶层 `Makefile` 目标**：
   - `make check-env`：检查 `go`, `node`, `npm` 版本并确认 `legacy/index.html` 存在。
   - `make setup`：安装前后端依赖（`cd web && npm install`、`cd server && go mod tidy`）。
   - `make test`：依次运行 `cd server && go test ./...` 与 `cd web && npm run typecheck && npx vitest run`。
   - `make build`：构建前端产物到 `web/dist`，并编译 Go 二进制到 `bin/creator` 和 `bin/legacy-export`。
   - `make release`：构建生产优化版包。
3. **`DocV6` 类型定义 (`web/src/core/schema/types.ts`)**：
   - 严格区分业务实体集合（`worlds`, `orgs`, `chars`, `templates`, `timeline`, `plots`, `scenes`, `glossary`, `stats`）与本地视图状态 `ui: { activeW, activeO, activeC, activeTpl, nowYear }`。
   - 所有实体具备 `id`, `name`, `data`, `createdAt`, `updatedAt`。

## 5. 验收标准与验证命令
```bash
cd /data/creator
make check-env
make setup
make test
```
- `go test ./...` 零错误通过。
- `npm run typecheck` 与 `npx vitest run` 零错误通过。
