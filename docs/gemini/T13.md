# T13 —— 部署套件（Nginx / Systemd / SQLite 在线备份 / 域名演进方案）

## 1. 背景与目标
针对当前机器（Ubuntu 22.04 LTS，初期无域名直接 IP/端口访问，后期无缝接入域名与 HTTPS）提供生产级一键部署与自动化运维套件：
1. **双模式平滑切换（无域名 HTTP 测试阶段 → 后期有域名 HTTPS 阶段）**：
   - `deploy/nginx.conf`：默认监听 `:80`（支持 IP 直接访问，`SECURE_COOKIE=false`），同时在注释块中预置完整的 Let's Encrypt (`certbot --nginx`) `:443` SSL 配置与 `SECURE_COOKIE=true` 切换指南。
   - Nginx 静态资源优化：`/assets/*` 设置 `Cache-Control: public, max-age=31536000, immutable`；`/index.html` 设置 `no-cache`；开启 `gzip_static` 与 `gzip`；`client_max_body_size 12m`；`/avatars/*` 直接 alias 到 `/var/lib/creator/avatars` 并加 `X-Content-Type-Options: nosniff` 防脚本执行。
2. **Go 单二进制内嵌静态资源兜底 (`embed.FS`)**：
   - 支持 `SERVE_STATIC=true` 环境变量：无需 Nginx 即可在当前机器直接单进程启动测试环境（自动处理 Vue Router History 模式回退到 `index.html`）。
3. **在线热备份（`creator backup` + `deploy/backup.sh`）**：
   - 在 `cmd/creator` 中提供 `creator backup --out /var/backups/creator` 子命令：使用 SQLite `VACUUM INTO`（兼容 WAL 模式的在线原子热备份，无需停机，无需外部依赖 `sqlite3` CLI）生成一致性数据库副本，并连同 `avatars/` 目录打包为 `.tar.gz`，自动清理超过 14 天的旧备份。
4. **Systemd 服务单元与部署脚本**：
   - `deploy/creator.service`：使用非 root 系统用户或指定工作目录运行，配置 `Restart=always`、内存与文件句柄限制、安全沙箱（`NoNewPrivileges=true`, `ProtectSystem=strict`）。

## 2. 产出文件清单
- `/data/creator/deploy/nginx.conf`
- `/data/creator/deploy/creator.service`
- `/data/creator/deploy/creator.env.example`（默认 `REGISTER_MODE=open`, `SECURE_COOKIE=false` 供无域名环境即刻使用）
- `/data/creator/deploy/backup.sh`
- `/data/creator/deploy/deploy.sh`
- `/data/creator/docs/DEPLOY.md`（含当前 Ubuntu 22.04 机器无域名快速部署、后期接入域名开启 HTTPS、备份恢复演练三部分完整步骤）
- `/data/creator/server/internal/store/backup.go`（`VACUUM INTO` 在线热备份实现及单测）

```bash
bash -n deploy/backup.sh
bash -n deploy/deploy.sh
cd server && go test -v ./internal/store/...
make build
```
